# CloudPulse Target Users

## User 1: Website owner

- **Example:** Runs an online store
- **Goal:** Know whether the website is available
- **Pain:** Learns about outages from customer complaints
- **Needs from CloudPulse:** Simple status view, alerts when the
  site goes down

## User 2: Backend developer

- **Example:** Maintains an API used by a mobile app
- **Goal:** Know the API responds correctly and quickly
- **Pain:** Slow or failing endpoints go unnoticed until users
  report bugs
- **Needs from CloudPulse:** Response-time charts, failure history

## User 3: DevOps engineer

- **Example:** Manages servers and deployments
- **Goal:** Detect outages, investigate incidents, measure
  availability
- **Pain:** No central record of when and why services failed
- **Needs from CloudPulse:** Incident timeline, uptime percentage,
  notifications

## Current experience of an outage

1. The service fails.
2. Nobody on the team knows.
3. Customers complain.
4. The team investigates with no history.
5. The service is fixed, but nothing is recorded.

## Experience with CloudPulse

1. The service fails.
2. CloudPulse detects it within minutes.
3. The team is notified.
4. The incident is recorded with start time, duration and recovery.
